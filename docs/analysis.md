# Анализ предметной области

## 1. Проблема

Существующие системы онлайн-бронирования столиков (OpenTable, Restoplace, Tomato)
либо перегружены функциями, либо требуют платной подписки, либо используют
тяжёлый стек (Node.js + React + PostgreSQL + JWT), что усложняет развёртывание
на типовом хостинге. Малым и средним ресторанам нужна простая, лёгкая система
бронирования на PHP + MySQL без сторонних фреймворков.

## 2. Целевая аудитория

| Роль | Кто это | Потребности |
|------|---------|-------------|
| Гость | Неавторизованный пользователь | Просмотр ресторанов, поиск, проверка доступности |
| Клиент (user) | Авторизованный пользователь | Бронирование, просмотр своих броней, профиль |
| Менеджер (manager) | Сотрудник ресторана | Управление бронями/залами/столиками своих ресторанов |
| Администратор (admin) | Владелец системы | Полный доступ через requireManager() |

## 3. Бизнес-процессы

1. Регистрация/вход клиента.
2. Поиск ресторана по названию, городу, кухне.
3. Проверка доступности столиков на дату/время/число гостей.
4. Создание брони со статусом pending.
5. Обработка брони менеджером → confirmed или cancelled.
6. Отмена брони клиентом.
7. Управление залами и столиками менеджером.

## 4. Ограничения

- Один менеджер привязан к одному или нескольким ресторанам.
- Столик принадлежит ровно одному залу.
- Бронь привязана к конкретному столику и пользователю.
- Длительность брони — 90 минут (по ТЗ).
- Занятые брони — статусы pending и confirmed.
- Пароли хранятся в виде хеша password_hash.
- Аутентификация — PHP-сессии (без JWT).

## 5. Аналоги

| Аналог | Плюсы | Минусы |
|--------|-------|--------|
| OpenTable | Мировой лидер, огромная база | Сложный, платный, не адаптирован под РФ |
| Restoplace | Российский, интеграция с CRM | Платный, требует обучения |
| Tomato | Простой интерфейс | Ограниченный функционал |
| RestBook (наш) | Простой, лёгкий, REST API, ролевая модель | Только базовый функционал |

index.php
Точка входа для всех API-запросов.
Отключает вывод ошибок в браузер, подключает все зависимости (bootstrap.php, auth-helpers.php, csrf.php, router.php), отправляет CORS-заголовки. Главная особенность — централизованный блок try/catch, который перехватывает все кастомные исключения и преобразует их в корректные HTTP-ответы с JSON-телом (401, 403, 404, 409, 422).

router.php
Маршрутизация запросов.
Содержит функцию route_dispatch($method, $uri), которая сопоставляет HTTP-метод и URI с нужным контроллером. Например, POST /api/bookings → BookingController::create(), а GET /api/admin/users → AdminController::users().

config.php
Параметры подключения к БД.
Возвращает массив с настройками: host, name (имя базы), user, pass, charset. Используется в bootstrap.php для создания PDO-соединения.

bootstrap.php
Инициализация окружения.
Создаёт PDO-соединение с MySQL (db()), запускает сессию (bootstrapSession()), настраивает CORS (sendCors()). Также содержит вспомогательные функции readJson() (парсинг тела запроса) и jsonOk() / jsonError() (отправка JSON-ответов).

auth-helpers.php
Проверка прав доступа.
Ключевые функции:

currentUser() — возвращает пользователя из сессии или null.

authenticate() — бросает AuthException, если сессии нет.

requireRole('admin', 'manager') — проверяет роль, бросает ForbiddenException.

requireManager() — сокращение для requireRole('manager', 'admin').

managerRestaurantId($id) — возвращает ID ресторана, привязанного к менеджеру.

csrf.php
CSRF-защита.
Генерирует токен (generateCsrfToken()), сохраняет его в таблице csrf_tokens и в сессии, проверяет заголовок X-CSRF-Token (validateCsrfToken()). Функция requireCsrf() вызывается в index.php для всех методов POST, PUT, DELETE, PATCH.

exceptions.php
Кастомные исключения.
Определяет классы AuthException (401), ForbiddenException (403), NotFoundException (404), ConflictException (409), ValidationException (422). Каждый класс соответствует определённому HTTP-статусу в index.php.

📂 Контроллеры (controllers/)
AuthController.php
Регистрация и аутентификация.

register() — валидация полей (логин, ФИО, email, телефон, пароль), проверка уникальности, хеширование пароля, INSERT в users.

login() — проверка логина/пароля через password_verify(), проверка is_blocked, создание сессии.

logout() — очистка сессии и cookie.

me() — возвращает текущего пользователя из сессии.

RestaurantController.php
Публичный каталог ресторанов.

list() — список ресторанов со статусом published, фильтрация по search, cuisine, пагинация.

show($id) — детали одного ресторана. Если ресторан не найден — NotFoundException.

TableController.php
Проверка доступности столиков (публичная).

availability() — принимает restaurantId, date, time, guests; возвращает список свободных столиков. Использует подзапрос NOT IN с ADDTIME для исключения занятых на 90 минут вперёд.

BookingController.php
Управление бронями пользователя.

create() — транзакция с FOR UPDATE, проверка пересечений, INSERT в bookings.

my() — список броней текущего пользователя с фильтром по статусу.

update($id) — редактирование только своих броней в статусе pending.

cancel($id) — отмена владельцем или менеджером ресторана.

delete($id) — удаление владельцем или администратором.

ManagerController.php
Панель менеджера.

bookings() — все брони ресторанов менеджера с фильтром по статусу и дате.

halls() — список залов ресторана менеджера.

tables() — список столиков ресторана менеджера.

createHall() — создание нового зала (только в своём ресторане).

createTable() — создание столика с проверкой принадлежности зала.

updateBooking($id) — смена статуса брони (confirmed/cancelled) с проверкой владения.

AdminController.php
Панель администратора.

stats() — сводная статистика (пользователи, брони, рестораны, блокировки).

bookings() — все брони с пагинацией, сортировкой (белый список) и фильтрами.

updateBooking($id) — полное редактирование брони (дата, время, гости, статус, комментарий).

updateBookingStatus($id) — смена только статуса.

deleteBooking($id) — удаление брони.

users() — список пользователей с пагинацией и фильтром по роли.

updateUserRole($id) — смена роли (запрет на снятие admin с себя).

toggleUserBlock($id) — блокировка/разблокировка (запрет на блокировку себя).

deleteUser($id) — удаление пользователя (запрет на удаление себя).

CsrfController.php
Выдача CSRF-токена.

getToken() — генерирует и возвращает токен для текущей сессии. Используется фронтендом при загрузке страницы.

🔧 Утилиты
install_admin.php
Установка паролей демо-пользователям.
Скрипт запускается один раз после импорта SQL-дампа. Генерирует хеши через password_hash() и обновляет записи в таблице users для логинов Conf2027, manager01, user01. После выполнения рекомендуется удалить файл с сервера.
